Scope: https://www.googleapis.com/auth/drive

Clem is a Windows desktop study and work app. The user links a Google Drive folder to a subject or project, and Clem works with the files in that folder. We use the full drive scope for these user-initiated features, each shown in the demo video:

1. Reading: the user browses their Drive in Clem to choose a folder; Clem lists the linked folder and its subfolders live, streams PDFs and videos from Drive when the user opens them, and reads a chosen file's content, or searches Drive, only to answer a question the user asks. Files are not copied to our servers.
2. Saving into the user's own folder: the user can drag a file into the linked Drive folder, use "Add files", and have worksheets Clem generates saved into that folder.
3. Updating the same file: when the user approves an edit Clem made to a file, the new version replaces the content of that same Drive file (no duplicate).
4. Managing files the user chooses: the user can rename a file or move it to Drive's trash from Clem. Clem never permanently deletes Drive files.

Why a narrower scope is not enough: drive.file only allows access to files the app created or the user picked. When the user picks their own existing folder, drive.file shows none of the files and subfolders already inside it, and it cannot add files to that folder. The user links their own existing folder, so listing it and saving into it requires the drive scope. drive.readonly cannot write at all. We do not request any broader scope than this one.

Data handling: Drive content is read live from Google and streamed; we store only an encrypted refresh token, deleted when the user chooses Disconnect, which also revokes the grant at Google. Excerpts of a file are sent to the AI provider the user chose only when the user asks about it. Clem's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. We do not use Google user data for advertising, do not sell it, and no person reads it except with the user's permission, for security or abuse investigation, or where the law requires.
